# =============================================================================

#
# Chapter 5 of the thesis: E3-DoH (Enhanced Evolutionary Encryption for
# Multi-Protocol DNS Security — DoH, DoT, DoQ).
#
# Every version is pinned. These are the versions under which
# expected_outputs/ was generated (see STATUS.md §5 for the full rationale).
# Do not bump a version without regenerating expected_outputs/ and the
# SHA-256 manifest in the same commit.
#
# Python version requirement:
#   The artifact runs under CPython 3.11.x. Python 3.12 is not supported
#   at the time of this writing because two transitive dependencies of
#   torch 2.1.2 have not published 3.12 wheels. Install via:
#       pyenv install 3.11.7 && pyenv local 3.11.7
#   or the equivalent for your environment manager.
#
# Installation:
#   pip install -r requirements.txt
#
# Tiered installation (toy mode only — CPU, no PCAP, no gRPC):
#   pip install -r requirements.txt --no-deps -c <(grep -v '^#' requirements.txt | \
#       grep -f <(echo -e 'numpy\nscipy\npandas\npyyaml\ntqdm\n'))
#   (The above is documented here for convenience; the supported path is the
#    full install. The full install takes ~6 min on a cold pip cache and
#    ~700 MB of disk. If you need a leaner install, see requirements-toy.txt,
#    which is generated by scripts/reproduce_all.sh --mode toy on first run.)
#
# =============================================================================

# -----------------------------------------------------------------------------
# Tier 4 — Homomorphic-encryption and lattice simulation (QHE, AEE)
# -----------------------------------------------------------------------------
# The thesis QHE layer uses Ring-LWE (n=256, q=4096; §5.3). AEE uses
# Module-LWE (n=1024, q≈2^32; §5.2.4). Both are simulated in this artifact
# rather than executed on a hardware accelerator; the numerical parameters
# match those in the thesis exactly, so that the reported latency figures
# (Table 26) are reproduced against the same lattice dimensions.

# pyfhel is the reference Python wrapper for the SEAL/CKKS/BFV backends.
# It is NOT used as the primary implementation — src/models/qhe_engine.py
# implements the Ring-LWE operations directly so that the selective-operation
# optimisations described in thesis §5.3.2 are visible in the code. pyfhel
# is included as a cross-check: tests/test_qhe.py runs the same arithmetic
# through pyfhel and asserts that the results agree to within 1 ULP.
pyfhel==3.4.2

# tenseal is used only by tests/test_qhe.py for the same cross-check on
# the CKKS backend. It is a smaller dependency than pyfhel and installs
# cleanly on CPU, which is why it is preferred for the automated test pass.
tenseal==0.3.15

# =============================================================================
# Version-bump policy
# =============================================================================
#
# A version bump is allowed only under the following conditions:
#
#   1. The bump is a patch-level bump (x.y.Z → x.y.Z+1) and no test fails
#      after the bump. Update STATUS.md §5 and this file in the same commit.
#      Do not regenerate expected_outputs/ — patch-level bumps are assumed
#      to be numerically identical and the verification script will catch
#      the assumption if it is wrong.
#
#   2. The bump is a minor-level bump (x.Y.z → x.Y+1.z) and the full
#      reproduction on the reference testbed still passes at the tolerances
#      recorded in REPRODUCIBILITY_CHECKLIST.md §5. Regenerate expected_outputs/
#      and MANIFEST.sha256 in the same commit, and append a changelog entry
#      to STATUS.md §11.
#
#   3. The bump is a major-level bump (X.y.z → X+1.y.z). This is treated as
#      a new artifact version. Bump the artifact version in STATUS.md §1,
#      regenerate everything, and append a full entry to the changelog.
#
# A bump that does not follow this policy will be rejected at review.
#
# =============================================================================
# Known environment issues
# =============================================================================
#
#   - torch 2.1.2 has no wheels for Python 3.12. Use Python 3.11.x.
#   - pyfhel 3.4.2 requires a C++ compiler on the host (gcc >= 10) even
#     though it ships prebuilt wheels for manylinux. On a minimal container
#     (e.g. python:3.11-slim) install build-essential first.
#   - aioquic 1.0.0 pulls in pylsqpack, which requires cmake on some
#     systems. The Dockerfile installs cmake explicitly.
#   - opacus 1.4.1 pins torch >= 2.0, <= 2.1.x. Do not bump torch to 2.2
#     without bumping opacus in the same commit and re-running the DP
#     calibration for Table 25.
#
# =============================================================================
